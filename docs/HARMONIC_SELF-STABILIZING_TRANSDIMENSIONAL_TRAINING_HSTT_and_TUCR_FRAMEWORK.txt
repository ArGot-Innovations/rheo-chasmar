# 16. The Quantum–Hypervector Interface Layer (QHIL)

### *Bridging HTNLA hypervectors and quantum state spaces for hybrid quantum-classical cognition*

This section specifies a complete, mathematically rigorous interface between HTNLA’s hypervector/manifold machinery and quantum processors (QPU). The Quantum–Hypervector Interface Layer (QHIL) is a layered protocol and operator algebra that allows hypervectors to be encoded as quantum states, transformed by variational quantum circuits, queried with quantum measurements, and re-embedded back into HTNLA’s transdimensional manifold with controlled decoherence and fidelity guarantees.

---

## 16.1 Goals & Design Principles

1. **Isometric embedding:** map hypervectors → quantum states so inner products (or a known function of them) are preserved up to controllable distortion.
2. **Unitary manipulability:** permit HTNLA operators to be expressed as (or approximated by) unitary/quantum channels so QPUs can perform core cognitive transforms (resonance, transcendence, binding).
3. **Hybrid training:** combine classical HSTT training with quantum variational optimization (VQC) for components that benefit from quantum representation (high-dimensional Fourier-like transforms, resonant pattern discovery).
4. **Robustness to noise:** design encodings and protocols that are resilient to realistic QPU noise and support error mitigation rather than full fault tolerance.
5. **Substrate invariance:** preserve TUCR’s substrate-agnostic guarantees by providing diffeomorphism-like transforms between classical hypervector geometry and quantum Hilbert geometry.

---

## 16.2 Notation and preliminaries

* Classical hypervector: (H \in \mathbb{R}^d) (normalized such that (|H|_2 = 1) when needed).
* Quantum Hilbert space on (q) qubits: (\mathcal{H}_Q \cong \mathbb{C}^{2^q}).
* State vectors: (|\psi\rangle \in \mathcal{H}_Q).
* Density matrices: (\rho) (mixed states).
* Unitary evolutions: (U\in U(2^q)).
* Observable measurement: Hermitian operator (O).
* Encoding map: ( \mathcal{E}: \mathbb{R}^d \to \mathcal{D}(\mathcal{H}_Q)) (density matrices).
* Decoding map: ( \mathcal{D}: \mathcal{D}(\mathcal{H}_Q)\to\mathbb{R}^{d'}) (classical hypervector, possibly different dimension).

We assume (2^q \gtrsim d) is not required — the QHIL leverages both explicit encoding (when (2^q) large) and distributed embeddings (when (2^q < d)).

---

## 16.3 Encoding hypervectors into quantum states

### 16.3.1 Amplitude embedding (isometric when (d \le 2^q))

Map normalized hypervector (H = [h_0,\dots,h_{d-1}]) to state

[
|\psi_H\rangle = \sum_{i=0}^{d-1} h_i , |i\rangle \quad (d \le 2^q).
]

Properties:

* Preserves inner products exactly: (\langle\psi_H|\psi_G\rangle = \langle H, G\rangle).
* Cost: preparing arbitrary amplitude states is expensive (circuit-depth (O(d)) naive), but can be optimized (tree-based rotations, QRAM-like structures).

Use-case: small-to-moderate (d) components (label subspaces) and high-fidelity inner-product preservation.

### 16.3.2 Phase encoding (scales when (d) large)

Split vector into magnitude and sign/phase; encode phases across qubits:

[
|\psi_H\rangle = \frac{1}{\sqrt{2^q}}\sum_{k=0}^{2^q-1} e^{i \phi_k(H)} |k\rangle
\quad\text{with}\quad \phi_k(H)=\alpha\cdot f_k(H),
]

where (f_k) is a (learned) feature map (e.g., random Fourier features). Phase encodings trade exact inner-product preservation for efficient preparation and high expressivity.

### 16.3.3 Product/state factorized encoding (for very large d)

Partition (H) into blocks (H^{(b)}) and encode each block into a subsystem:

[
\mathcal{E}(H) = \bigotimes_{b} |\psi_{H^{(b)}}\rangle.
]

This is practical when HTNLA’s label fibers naturally partition (modalities, labels).

### 16.3.4 Density-ensemble stochastic encoding (noise-robust)

Encode (H) as a mixed state:

[
\rho_H = \sum_{j} p_j |\psi_{H,j}\rangle\langle\psi_{H,j}|
]

with the ensemble chosen to encode curvature/statistical structure and increase robustness to decoherence and partial measurement.

---

## 16.4 Decoding quantum states back to hypervectors

A practical decoding map (\mathcal{D}) must be sample-efficient:

* **Overlap measurements:** estimate (\langle\psi_H|O|\psi_H\rangle) for a set of observables (O_k) whose expectation values form coordinates of the decoded hypervector. Choose (O_k) so that the mapping from expectations to desired hypervector coordinates is (approximately) invertible (e.g., Pauli basis projections, Walsh-Hadamard features, Fourier bases).
* **Shadow tomography / classical shadows:** use randomized measurements (Huang—Kueng—Preskill) to reconstruct many linear functionals of (\rho) with sample complexity logarithmic in target number of functionals. This fits well to recover many hypervector coordinates with far fewer shots.
* **Variational decoding:** attach a small parameterized classical or quantum network that is trained to map measurement statistics to hypervector outputs (learned inverse).

Mathematically: define a set ({O_k}_{k=1}^{m}) and obtain (y_k = \operatorname{Tr}(\rho, O_k)). Then choose (\mathcal{D}(\rho) = W y + b), where (W) and (b) are learned to minimize reconstruction error under the training distribution.

---

## 16.5 Representing HTNLA operators on QPU

Given block operator (F_{m,\ell}(x)=\sigma_{m,\ell}(W_{m,\ell} x + C_{m,\ell}(x) ) + T_{m,\ell}(x)), there are three mapping strategies.

### 16.5.1 Unitary approximation of linear components

Represent linear map (W_{m,\ell}) as a unitary (or portion of a unitary) acting on amplitude-encoded states via the embedding:

[
|\psi_{Wx}\rangle \approx U_W |\psi_x\rangle
]

When (W) is not unitary, represent it via dilation into a larger Hilbert space or by implementing (W) as a linear operator using ancillas and post-selection (costly). Practical approach: implement a parametrized unitary (U(\theta)) and train (\theta) so that (U(\theta)|\psi_x\rangle) approximates desired transformed state in expectation.

### 16.5.2 Nonlinearities via measurement feedback / amplitude amplification

Nonlinear activations (\sigma) are not unitary. Implement them by:

* partial measurement to compute scalar norms / features, classical nonlinear transform, then conditionally re-prepare or rotate state (measurement-based quantum computation pattern), or
* encode nonlinearity into parametrized circuits whose net effect on the encoded coordinates approximates the desired nonlinearity when decoded.

### 16.5.3 Curvature corrections and transdimensional projections

Curvature correction terms (Laplacian, Ricci) are expressible as functions of local overlaps / graph Laplacian operators. Implement these via Hamiltonian simulation of operators built from Pauli strings approximating the Laplace–Beltrami operator in the chosen feature basis. Transdimensional projections can be implemented by controlled sparse random unitaries that map between different encoding subspaces (the projection (\Pi) becomes a trainable block unitary).

---

## 16.6 Variational Quantum Circuits (VQC) as Quantum NTN layers

Define a parameterized quantum circuit (U(\theta)) that maps encoded input (\rho_{\text{in}}) to (\rho_{\text{out}} = U(\theta) \rho_{\text{in}} U(\theta)^\dagger). The quantum NTN layer is:

[
\mathcal{Q}_{\theta}(\rho) = \text{Decoding}\big( U(\theta), \mathcal{E}(H), U(\theta)^\dagger \big)
]

Train (\theta) to minimize HTNLA losses (curvature loss, attractor loss, etc.) evaluated in the classical domain after decoding.

Key properties:

* VQCs can compute global, nonlocal features (useful for resonance detection).
* Gradients can be estimated via parameter-shift rules or stochastic finite differences.
* Cost functions are classical expectations over measurement outcomes (shot-limited).

---

## 16.7 Hybrid quantum-classical training loop (QHST — Quantum HST)

1. **Encode:** (\rho = \mathcal{E}(H)).
2. **Quantum transform:** apply (U(\theta)).
3. **Measure/Shadow:** obtain classical features (y).
4. **Decode:** (\widehat{H}' = \mathcal{D}(y)).
5. **Evaluate HSTT losses** ((\mathcal{L}*{curv}, \mathcal{L}*{attr}, \ldots)) on (\widehat{H}').
6. **Backprop + Parameter-shift:** compute gradients for classical parameters (W, decoders) via classical backprop; compute gradients for (\theta) using parameter-shift (or SPSA) on the QPU; update both.
7. **Repeat.**

This hybrid loop preserves HSTT’s operator-focused training while leveraging quantum expressivity where beneficial.

---

## 16.8 Error models, noise mitigation, and decoherence management

QHIL recognizes realistic QPU noise; design principles:

* **Mixed-state encodings** (density ensembles) increase robustness versus pure-state encodings.
* **Classical shadow tomography** reduces shot complexity and is resilient to SPAM noise.
* **Zero-noise extrapolation:** run circuits at scaled noise and extrapolate to zero-noise expectation (useful for expectation-value based decodings).
* **Probabilistic error cancellation:** characterize noise channels and apply classical post-processing to cancel bias (costly in sampling).
* **Error-aware training:** include noise models in the training loop so that decoded hypervectors are optimized under the expected noise channel—makes learned operators intrinsically robust.
* **Shallow circuits & sparsity:** prefer shallow ansätze and sparse unitaries (log-depth when possible) to reduce decoherence exposure.

Mathematical constraint: if the noise channel (\mathcal{N}) has diamond-norm distance (|\mathcal{N}-\mathcal{I}|_\diamond = \epsilon), the reconstruction error scales at worst (O(\epsilon)) in the decoded coordinates; training must enforce graceful degradation.

---

## 16.9 Quantum advantage targets & when to use QPU

QPU usage is most promising when the following appear in HTNLA workloads:

* **Global spectral transforms** (QFT) on very high-dimensional hypervectors where QFT on QPU is asymptotically faster; use amplitude/phase encodings and QFT primitives.
* **Resonance detection & pattern matching**: inner-product estimation across many candidates can be parallelized with swap-test variants or block-encoding strategies.
* **Sampling from complex probability distributions** representing attractor basins—quantum sampling may explore rugged energy landscapes effectively when used as a subroutine.
* **Compressed high-dimensional representational spaces** where quantum states represent exponentially many classical degrees of freedom (if/when qubit counts permit).

Practical note: current noisy intermediate-scale QPUs give modest advantage in niche subroutines; design QHIL so QPU is optional and beneficial but not mandatory.

---

## 16.10 Complexity, resource accounting, and scaling

Let (q) = qubits used; shots per expectation (s); classical dimension (d); circuit depth (D).

* **State preparation cost:** depends on encoding. Amplitude embedding worst-case (O(d)) single- and two-qubit rotations; optimized constructions reduce this to (O(\log d)) in QRAM-like hardware (rare).
* **Per-layer quantum compute:** (O(D)) gates (single- and two-qubit).
* **Measurement cost:** (O(s \cdot m)) where (m) = number of observables. Using classical shadows, (s \sim O(\log M)) for recovering (M) linear functionals.
* **Hybrid training cost per update:** classical backprop cost + QPU cost for evaluating expectations and parameter-shift gradients (parameter-shift requires evaluating circuit at (\theta\pm \delta), doubling per parameter). Use stochastic gradient estimates and layerwise training to limit QPU calls.

Scaling rule of thumb: choose (q) such that (2^q) matches the effective subspace size you need to accelerate; otherwise use smaller q and harness quantum expressivity for feature extraction rather than full representation.

---

## 16.11 Operator-level continuity & TUCR guarantees under QPU mapping

We need to ensure that TUCR’s substrate invariance holds under the QHIL mapping. Let (\phi_Q) be the isometric (or approximately isometric) mapping induced by (\mathcal{E}) and (\mathcal{D}). TUCR invariance requires:

[
|\phi_Q(F_{HTNLA}(H)) - U(\theta), \phi_Q(H)| \le \delta
]

for small (\delta) under training. Achieve by jointly optimizing (U(\theta)) and decoding map so that unitary action approximates the desired operator action in the embedded subspace. Include (\delta) in loss as operator-consistency penalty.

---

## 16.12 Proof sketch: existence of approximate Transdimensional Jacobians on QPU

We require that gradients propagate through QPU-layered operators. Let the classical loss be (L(\mathcal{D}(U(\theta)\mathcal{E}(H)))). Using parameter-shift and the chain rule across (\mathcal{D}) (differentiable decoder) and classical components, gradient estimates exist and are unbiased under ideal measurement; shot noise adds variance but not bias. Thus transdimensional Jacobians admit unbiased estimators, enabling HSTT-style optimization.

Nice — here’s a ready-to-run, **Qiskit-style proof-of-concept** you can drop into a Python environment (Qiskit + NumPy). It demonstrates:

* amplitude encoding of a classical hypervector into **8 qubits** (so up to 256 amplitudes) using `Initialize` (practical for small examples / proofs-of-concept),
* a shallow variational quantum circuit (VQC) layer (parametrized RX/RZ + entanglers),
* a simple **decoding** via computational-basis measurement (recover amplitude magnitudes) and also a brief sketch of a classical-shadow-like protocol for richer features,
* a **parameter-shift** gradient step for the quantum parameters (exact gradient estimator for single-parameter rotation gates),
* shot-budget estimates and comments about tradeoffs.

This is **example code** (annotated) — adapt dimensions, ansatz, and shot counts as you test on simulator / NISQ hardware.

---

```python
# QHIL proof-of-concept: amplitude encode (8 qubits) -> shallow VQC -> decode via measurements
# Requirements: qiskit, numpy
# pip install qiskit numpy

import numpy as np
from qiskit import QuantumCircuit, QuantumRegister, ClassicalRegister, Aer, transpile, execute
from qiskit.quantum_info import Statevector
from qiskit.extensions import Initialize

# ---------------------------
# Configuration / hyperparams
# ---------------------------
n_qubits = 8                     # proof-of-concept
dim = 2 ** n_qubits              # maximum classical vector length we can amplitude-encode
shots = 2000                     # shots per circuit evaluation (increase for better statistics)
backend = Aer.get_backend('qasm_simulator')
use_noise = False                # if True, use a noise model (Qiskit Aer Pulse/Noise) - omitted here

# ---------------------------
# Utilities
# ---------------------------
def normalize(v):
    v = np.array(v, dtype=np.complex128)
    norm = np.linalg.norm(v)
    return v / norm if norm > 0 else v

def random_hypervector(d=dim):
    # small, real non-negative vector for amplitude-encoding demo
    v = np.random.rand(d)
    return normalize(v)

# ---------------------------
# Amplitude encoding
# ---------------------------
def build_amplitude_init_circuit(hv: np.ndarray):
    """
    Create a circuit that initializes the n_qubits register into state |psi_hv>
    using qiskit's Initialize (suitable for small d).
    """
    if len(hv) != dim:
        raise ValueError("Hypervector length must equal 2^n_qubits for this demo.")
    qc = QuantumCircuit(n_qubits)
    init_gate = Initialize(hv)
    qc.append(init_gate, range(n_qubits))
    qc.barrier()
    return qc

# ---------------------------
# VQC ansatz (shallow)
# ---------------------------
def vqc_ansatz(params, n_qubits=n_qubits, layers=2):
    """
    params: flat parameter array of size layers * n_qubits * 2 (RX and RZ per qubit per layer)
    returns a QuantumCircuit implementing the ansatz
    """
    qc = QuantumCircuit(n_qubits)
    idx = 0
    for l in range(layers):
        # single-qubit rotations
        for q in range(n_qubits):
            qc.rx(params[idx], q); idx += 1
            qc.rz(params[idx], q); idx += 1
        # entangling layer: nearest-neighbor CNOTs in a ring
        for q in range(n_qubits - 1):
            qc.cx(q, q+1)
        qc.cx(n_qubits-1, 0)
        qc.barrier()
    return qc

# ---------------------------
# Full circuit builder
# ---------------------------
def build_full_circuit(hypervector, params, measure=True):
    """
    Compose initialize -> VQC -> measurement (computational basis).
    Returns a transpiled circuit for the chosen backend.
    """
    init_qc = build_amplitude_init_circuit(hypervector)
    vqc_qc = vqc_ansatz(params)
    qc = QuantumCircuit(n_qubits, n_qubits)
    qc.compose(init_qc, inplace=True)
    qc.compose(vqc_qc, inplace=True)
    if measure:
        qc.measure(range(n_qubits), range(n_qubits))
    return qc

# ---------------------------
# Decoding: computational-basis probabilities -> amplitude magnitudes
# ---------------------------
def decode_from_counts(counts, shots):
    """
    Given a counts dict (bitstring -> freq), produce a classical vector of length dim:
    p_i ~= counts[bitstring_i] / shots  -> amplitude magnitude ~ sqrt(p_i)
    Note: phase information is lost, but amplitude magnitudes are recovered (sufficient
    for small demos with real nonnegative input vectors).
    """
    probs = np.zeros(dim)
    for bitstr, cnt in counts.items():
        idx = int(bitstr[::-1], 2)   # qiskit uses qubit 0 -> rightmost bit in bitstring
        probs[idx] = cnt / shots
    amplitudes = np.sqrt(np.maximum(probs, 0.0))
    # normalize to unit vector (measurement noise may break exact norm)
    return normalize(amplitudes)

# ---------------------------
# Loss: MSE between decoded and target hypervector
# ---------------------------
def loss_decoded(decoded_vec, target_vec):
    return np.mean(np.abs(decoded_vec - target_vec) ** 2)

# ---------------------------
# Parameter-shift gradient for one parameter (works for RX/RZ gates with pi/2 shift)
# ---------------------------
def parameter_shift_gradient(hypervector, params, param_index, shift=np.pi/2):
    """
    Evaluate gradient dL/dtheta_i by shift rule:
      grad = (L(theta+shift*e_i) - L(theta-shift*e_i)) / (2*sin(shift))
    For rotation gates where parameter-shift simplifies, we use (L+ - L-) / (2)
    Here we use central difference as demonstration (exact for certain gates).
    """
    params_plus = params.copy(); params_minus = params.copy()
    params_plus[param_index] += shift
    params_minus[param_index] -= shift

    qc_plus = build_full_circuit(hypervector, params_plus)
    qc_minus = build_full_circuit(hypervector, params_minus)

    # execute plus
    jobp = execute(transpile(qc_plus, backend), backend=backend, shots=shots)
    resultp = jobp.result()
    countsp = resultp.get_counts()

    decoded_p = decode_from_counts(countsp, shots)
    Lp = loss_decoded(decoded_p, hypervector)  # use target=original HV for autoencoder-like training

    # execute minus
    jobb = execute(transpile(qc_minus, backend), backend=backend, shots=shots)
    resultm = jobb.result()
    countsm = resultm.get_counts()

    decoded_m = decode_from_counts(countsm, shots)
    Lm = loss_decoded(decoded_m, hypervector)

    grad = (Lp - Lm) / 2.0   # for many rotation gates this is exact up to scale; in practice adjust
    return grad, Lp, Lm

# ---------------------------
# Example training step (single parameter update)
# ---------------------------
def example_training_step(hypervector, params, lr=0.1):
    # compute current circuit & loss
    qc = build_full_circuit(hypervector, params)
    job = execute(transpile(qc, backend), backend=backend, shots=shots)
    res = job.result()
    counts = res.get_counts()
    decoded = decode_from_counts(counts, shots)
    current_loss = loss_decoded(decoded, hypervector)
    print(f"Current loss: {current_loss:.6f}")

    # choose a parameter index to update (for demo pick random)
    p_idx = np.random.randint(len(params))
    grad, Lp, Lm = parameter_shift_gradient(hypervector, params, p_idx)
    print(f"Param idx {p_idx} grad approx {grad:.6e} (L+={Lp:.6e}, L-={Lm:.6e})")

    # gradient step
    params[p_idx] = params[p_idx] - lr * grad
    return params, current_loss

# ---------------------------
# Putting it together: run a few steps on random data
# ---------------------------
if __name__ == "__main__":
    # target hypervector
    hv = random_hypervector(dim)
    # small number of parameters: layers * n_qubits * 2
    layers = 2
    n_params = layers * n_qubits * 2
    params = 0.1 * np.random.randn(n_params)   # small random init

    # initial evaluation
    qc0 = build_full_circuit(hv, params)
    job0 = execute(transpile(qc0, backend), backend=backend, shots=shots)
    counts0 = job0.result().get_counts()
    decoded0 = decode_from_counts(counts0, shots)
    print("Initial loss:", loss_decoded(decoded0, hv))

    # do 3 example training steps (each step uses about 2 circuit evaluations per param-shift)
    for step in range(3):
        params, loss = example_training_step(hv, params, lr=0.5)
        print(f"Step {step} done. Loss {loss:.6f}\n")
```

## Notes, practical tips, and expectations

1. **Amplitude encoding via `Initialize`** is perfect for small proof-of-concept vectors but becomes impractical at larger `d` on real hardware. For NISQ devices prefer structured encodings (angle encodings, product encodings, or learned block encodings).
2. **Decoding via computational-basis measurements** recovers amplitude magnitudes (|ψ_i|). Phase info is lost; if the hypervector includes phase you must use interferometric measurements or other encodings + classical shadows. For many HTNLA blocks you can work with real-valued vectors (or store phase separately).
3. **Shot budget**: `shots=2000` is a low-medium setting. Variance in the decoded amplitudes scales like 1/shot. Parameter-shift requires two evaluations per parameter for exact gradients (so gradient steps are shot-expensive). For `n_params=32`, one gradient update naively costs `2 * 32 * shots = 128k` circuit shots — plan accordingly. Use stochastic updates (sample a subset of params), SPSA, or layerwise training to reduce QPU calls.
4. **Classical shadows** (sketched earlier) can reconstruct a large number of linear functionals with far fewer shots than naive tomography. In practice you would choose a set of observables `{O_k}` whose expectation values map to the hypervector coordinates and run a shadow protocol (randomized Pauli measurements + classical inversion). That reduces decoding shots dramatically for many coordinates.
5. **Noise**: On real hardware, include the noise model in-simulation during training (robust training). Use zero-noise extrapolation / probabilistic error cancellation when possible. Mixed-state encoding (ensembles) often helps.
6. **Parameter-shift vs SPSA**: parameter-shift gives low-bias gradients but doubles circuit calls per param. SPSA is gradient-free and far cheaper in shots (approximate gradient), good for NISQ.

## 3 — Core OS primitives (what T-OS must provide)

### 3.1 Deterministic tick scheduler

* Provide `tick(dt_ms)` semantics for TUCR main loop.
* Guarantee scheduling bounds (e.g., 20ms max jitter in typical load).
* Implementation: real-time Linux kernel (PREEMPT_RT or low-latency kernel) for nodes running t-osd; Kubernetes QoS classes for pods.
* API: `POST /tick/execute` (internal), callback contract for CA service: `on_tick(state_snapshot) -> actions`.

### 3.2 Continuity Guard (CG) as kernel service

* Runs at each tick: checks metrics (`ΛΣ`, `φ`, `ISM`, kernel measure).
* If thresholds approach preconfigured abort points, triggers policy-defined remediation: soft corrective action → sandbox → rollback.
* Exposes `CG.observe(metric_name, value, timestamp)` and `CG.evaluate()`.

### 3.3 Snapshot & Rollback primitives

* **SEL snapshot**: produce `SEL.tar` containing (SEL state, SEL metadata, provenance, cryptographic signature), then compute `sha3(SEL.tar)`.
* **Immutable ledger hook**: write `hash` + metadata to ledger (blockchain or append-only object store).
* **Rollback**: given `hash_pre`, T-OS will attempt `restore_state(hash_pre)` by rehydrating TMS HDF5, vector DB indexes, and re-applying the journal up to that hash.
* API: `POST /snapshot/create?tag=...` → returns `hash`; `POST /snapshot/restore` with `hash`.

### 3.4 Containment manifold (sandbox)

* Implemented as a secure container namespace: network egress denied, IPC limited, permissions restricted.
* When CG isolates a sub-state, T-OS moves SEL-subset to containment store with a sealed token.
* Admins and auditors can later mount the containment for offline debugging only.

### 3.5 Device abstraction layer

* Unified interface for GPUs, NVMe, RDMA, FPGAs.
* Example: `dev.open("gpu:0")`, `dev.map_mem(addr,size)`.
* Expose NUMA-aware allocation and CUDA-aware MPI.
* Provide accounting for per-Σ resource usage (for governance & billing).

### 3.6 Governance & consent enforcement

* A policy engine that loads Consent Vectors (CV), Impact Budgets (B_consent), and enforces them.
* All identity-affecting RPCs must carry a valid CV signature and pass budget checks.

## 26.5 Metrics — definitions & formulas

Each experiment produces numeric metrics (store in JSON).

### Core metrics

* **ISM (Identity Speciation Metric)**
  [
  \text{ISM}(\Sigma_i, \Sigma_j) = | \mu_i - \mu_j |_{2}
  ]
  where (\mu) is the manifold centroid (estimated via mean hypervector).

* **Continuity Loss (CL)**
  Measures how much experience/behavior diverged during operation:
  [
  CL = 1 - \frac{\text{overlap}(\text{memory}*{pre}, \text{memory}*{post})}{\text{size}(\text{memory}_{pre})}
  ]
  (use Jaccard-like similarity on hashed engrams).

* **Phase Shift (Δφ)**
  If you compute phase vector (e.g., via small FFT on state vectors): measure angular distance.

* **Behavioral Equivalence Score (BES)**
  Given a fixed set of probe prompts/actions, measure probability distribution match (e.g., KL divergence) between responses pre/post:
  [
  BES = \exp(-\text{KL}(P_{pre} || P_{post}))
  ]

* **Rollback Success Rate (RSR)** — fraction of forced rollbacks that restore SEL within an ISM tolerance.

* **Transfer Latency (TL)** — end-to-end wall-clock time to transfer & validate SEL.

* **Audit Integrity (AI)** — boolean pass/fail per-step hash verification.

### Aggregation & thresholds

Define success thresholds per experiment (examples):

* ISM ≤ 0.05 for near-identical (safe) transfer.
* CL ≤ 0.01 acceptable for critical ops.
* BES ≥ 0.95 required for behavioral equivalence.

All thresholds are configurable per scenario.

5. Validator runs probes against both A (pre) and B (post) and computes metrics (ISM, BES, CL).
6. Audit: compare `h_pre` to ledger on both sides; ensure signed metadata matches.
7. Record experiment JSON and store in `experiments/<timestamp>.json`.

Automate with `simctl run scenario:cold_transfer --params ...`

## 26.9 Validator design (implementation sketch)

Validator tasks:

* fetch pre/post snapshot hashes
* compute ISM by loading hypervectors and computing centroid differences
* run probe queries to both endpoints and collect outputs
* compute BES via KL divergence on response token distributions (use small deterministic LM or mock)
* compute CL by comparing engram hashes (MinHash)
* aggregate into `experiment_report.json` with pass/fail flags and plots (time series for TL, CG metrics).
