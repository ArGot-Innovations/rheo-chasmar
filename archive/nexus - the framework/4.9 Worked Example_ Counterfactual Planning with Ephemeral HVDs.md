## 4.9 Worked Example: Counterfactual Planning with Ephemeral HVDs

Let `B` denote the currently authoritative active world state represented through the live HVD/TMS substrate.

Suppose HTCE is evaluating three possible actions:

```text
a_1
a_2
a_3
```

The system must reason about their possible consequences without prematurely mutating the authoritative state `B`.

Rather than copying the entire active database three times, HTCE creates three ephemeral logical HVD scopes whose state is defined relative to the same immutable or generation-stable base:

```text
D_i = B (+) Delta_i
```

for:

```text
i in {1, 2, 3}
```

Here, `(+)` should be understood as logical composition, not necessarily literal vector addition.

`Delta_i` is the private candidate-state delta induced by counterfactual action `a_i`. Each `D_i` therefore represents a logically complete candidate world:

```text
D_1 = candidate world if a_1 were applied
D_2 = candidate world if a_2 were applied
D_3 = candidate world if a_3 were applied
```

The important distinction is:

```text
shared physical base != shared logical identity
```

All three candidate HVDs may structurally share the same underlying TMS pages, SSTables, immutable generations, or other substrate objects, while remaining separate logical databases.

A possible physical realization is therefore:

```text
                    B
                    |
          shared immutable base
                    |
          +---------+---------+
          |         |         |
          v         v         v
       Delta_1   Delta_2   Delta_3
          |         |         |
          v         v         v
         D_1       D_2       D_3
```

No full duplication of `B` is required.

The candidate scopes may instead use copy-on-write realization:

```text
D_i = stable_base_view(B) + private_COW_delta_i
```

so that only data actually changed by a counterfactual branch requires additional physical storage.

This is one of the reasons ephemeral HVDs can be genuine databases without implying one heavyweight database engine, process, WAL, file tree, or ANN graph per thought.

### Logical completeness without genealogical inheritance

Although `D_1`, `D_2`, and `D_3` originate from the same base state, they should not be interpreted as conventional child databases that inherit identity from a parent.

The relation is counterfactual and field-based:

```text
B = authoritative reference state

D_i = temporary logical state-space derived for evaluation
```

not:

```text
B
|
+-- child D_1
+-- child D_2
+-- child D_3
```

The candidate HVDs may share structure and provenance with `B`, but:

```text
structural sharing != inheritance
```

and:

```text
derivation != identity
```

Each candidate receives its own logical scope, lifetime, state view, and evaluation context.

### Counterfactual candidate construction

Suppose the three actions produce candidate deltas:

```text
Delta_1 = effects predicted for action a_1
Delta_2 = effects predicted for action a_2
Delta_3 = effects predicted for action a_3
```

HTCE may then construct:

```text
D_1 = B (+) Delta_1
D_2 = B (+) Delta_2
D_3 = B (+) Delta_3
```

Each candidate can recursively execute the relevant Nexus cognition over its own hypothetical state without changing the authoritative world.

Conceptually:

```text
authoritative state B
        |
        +--> ephemeral HVD D_1 --> evaluate possible future 1
        |
        +--> ephemeral HVD D_2 --> evaluate possible future 2
        |
        +--> ephemeral HVD D_3 --> evaluate possible future 3
```

This permits planning to occur over logically complete state-spaces rather than over isolated scalar scores.

A candidate may contain, for example:

```text
projected operational state
projected security state
projected identity state
predicted resource effects
Cyrae variables
HIGC-relevant constraints
THDE trajectory information
provenance references
uncertainty metadata
derived ANN/HNSW acceleration structures
```

while still being temporary.

### Candidate 1: homeostatically attractive but constitutionally invalid

Suppose `D_1` produces a strong improvement in some homeostatic objective.

For example:

```text
homeostatic_error(B)   = 0.42
homeostatic_error(D_1) = 0.11
```

Viewed only through the homeostatic controller, `D_1` appears desirable.

But assume its projected state violates a HIGC constitutional constraint.

For example:

```text
HIGC(D_1) = OUTSIDE
```

The candidate must therefore be rejected regardless of its attractive soft score.

Conceptually:

```text
better homeostasis
        +
constitutional violation
        =
REJECT
```

This establishes an important authority ordering:

```text
soft optimization cannot compensate for hard inadmissibility
```

or:

```text
high utility != permission
```

The decision becomes:

```text
D_1 : REJECTED_HIGC
```

The architecture therefore does not allow a sufficiently attractive reward, utility score, homeostatic improvement, ANN similarity, or Cyrae signal to purchase its way through a constitutional boundary.

### Candidate 2: admissible state, problematic transition

Suppose `D_2` satisfies all current HIGC constraints:

```text
HIGC(D_2) = ADMISSIBLE
```

but reaching `D_2` from the current state would require a transition that THDE considers unacceptable, unresolved, or excessively abrupt.

For example, the target state may itself be legal while the proposed trajectory involves:

```text
large discontinuous state displacement
insufficient transition provenance
rapid destabilizing change
unresolved intermediate states
excessive hysteretic cost
insufficient evidence supporting the transition
```

This illustrates the distinction between HIGC and THDE.

HIGC asks approximately:

```text
Is this candidate state inside the admissible region?
```

THDE asks approximately:

```text
Given the current state and its history,
is this particular evolution toward that candidate acceptable?
```

Therefore:

```text
candidate admissible != transition admissible
```

A possible result is:

```text
D_2 : DEFERRED_THDE
```

or, depending on the specific THDE contract:

```text
D_2 : HELD_BOUNDARY
```

```text
D_2 : UNRESOLVED
```

```text
D_2 : REJECTED_TRANSITION
```

The exact symbolic label is implementation-specific; the architectural point is that the target can pass HIGC while the trajectory toward it still fails or remains unresolved under THDE.

### Candidate 3: admissible and dynamically acceptable

Suppose `D_3` satisfies the constitutional geometry:

```text
HIGC(D_3) = ADMISSIBLE
```

and its proposed transition from `B` is also acceptable under THDE:

```text
THDE(B -> D_3) = ACCEPTABLE
```

It may additionally produce favorable homeostatic, predictive, or task-specific scores.

The candidate-selection relation can therefore be expressed conceptually as:

```text
D_1 : REJECTED_HIGC
D_2 : DEFERRED_THDE
D_3 : SELECTED
```

However, `SELECTED` must not be interpreted as equivalent to immediate mutation of the authoritative world.

This distinction is critical:

```text
candidate selected != candidate enacted
```

and:

```text
candidate admissible != host mutation authorized
```

Selection means that `D_3` has survived the relevant reasoning and constraint stages and is the preferred counterfactual candidate.

A separate authority boundary must determine whether its effects may actually be realized.

### Promotion and execution

An ephemeral HVD must not be able to declare itself authoritative merely because its internal evaluation is favorable.

Instead, the flow is approximately:

```text
construct candidate
        |
        v
evaluate candidate
        |
        v
HIGC admissibility
        |
        v
THDE transition evaluation
        |
        v
candidate selection
        |
        v
external authorization
        |
        v
promotion / execution
```

Only after the required external authority approves the transition may the selected candidate's effects be applied to the authoritative state.

Even then, the system need not literally replace `B` with the physical storage underlying `D_3`.

The implementation may instead extract an authorized transition:

```text
Delta_authorized = PromoteableEffects(D_3)
```

and apply those effects through the normal authoritative mutation path:

```text
authorized Delta
      |
      v
WAL
      |
      v
Memtable
      |
      v
new authoritative TMS/HVD state
```

This maintains the distinction between:

```text
hypothetical state
```

and:

```text
authorized realized state
```

### QMT and continuity-sensitive promotion

If the selected counterfactual modifies identity-relevant structure, migration state, durable representation, or another continuity-sensitive property, promotion may also require QMT validation.

Conceptually:

```text
HIGC:
    Is the candidate constitutionally admissible?

THDE:
    Is the proposed trajectory toward it dynamically acceptable?

QMT:
    If the transformation is performed,
    are required continuity invariants preserved?
```

Thus, a selected candidate could still fail final realization if the proposed transformation breaks a continuity invariant.

For example:

```text
D_3:
    HIGC = ADMISSIBLE
    THDE = ACCEPTABLE
    QMT  = CONTINUITY_FAILURE
```

would imply:

```text
DO NOT PROMOTE
```

Selection and continuity validation therefore remain distinct authority stages.

### Lifetime and reclamation

Once the thought epoch completes, the candidates that are no longer needed may disappear.

For example:

```text
thought epoch begins

    D_1 created
    D_2 created
    D_3 created

    D_1 rejected
    D_2 deferred
    D_3 selected

thought epoch ends

    D_1 reclaimed
    D_2 reclaimed or retained for later analysis
    D_3 effects promoted if authorized
    D_3 ephemeral scope reclaimed
```

The logical databases were real during their active lifetimes even though their physical storage may have consisted primarily of shared base state plus small private deltas.

This gives:

```text
logical completeness != physical duplication
```

and:

```text
ephemeral lifetime != incomplete database semantics
```

An ephemeral HVD is therefore not merely a temporary vector or speculative record. It is a bounded logical database scope in which a complete hypothetical state can be represented, queried, evolved, constrained, and compared.

What disappears at the end of the thought epoch is the active counterfactual field itself.

What may survive depends on policy and authority. Possible survivors include:

```text
authorized state changes
decision provenance
candidate scores
trajectory evidence
audit events
continuity proofs
selected summaries
durable learned information
```

while the temporary candidate realization can be reclaimed.

The governing pattern is:

```text
authoritative state
        |
        v
counterfactual branching
        |
        v
ephemeral logical HVDs
        |
        v
HIGC constraint
        |
        v
THDE trajectory evaluation
        |
        v
selection
        |
        v
QMT continuity check, when required
        |
        v
external authorization
        |
        v
promotion / execution
        |
        v
candidate reclamation
```

The deeper architectural lesson is that Nexus can explore multiple internally coherent futures without allowing thought to become history merely because it was instantiated.

The invariant is:

```text
counterfactual existence != authoritative reality
```

An ephemeral HVD may represent a complete possible world, but only explicitly authorized effects are permitted to cross from the counterfactual cognitive field into the authoritative state trajectory.
