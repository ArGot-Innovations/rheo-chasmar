## 5. HTLA: Heterogeneous Labeled State as a Direct Sum

Hypervector Linear Transdimensional Algebra (HTLA) provides the stable **linear mathematical interface** for heterogeneous state inside HVD.

Its purpose is not to claim that heterogeneous data become homogeneous merely because they can be stored in one database. The opposite is intended: HTLA provides a formal representation in which components with different dimensions, coordinate systems, semantics, and physical interpretations can participate in one logical state while retaining explicit type boundaries.

Let `L` be a finite set of semantic labels. For every label `l in L`, associate a finite-dimensional real vector space

\[
V_l = \mathbb R^{n_l},
\]

where `n_l` is the dimensionality assigned to component `l`.

The complete HTLA state space is then

\[
\boxed{
\mathcal H
=
\bigoplus_{l\in L} V_l
=
\bigoplus_{l\in L}\mathbb R^{n_l}
}
\]

and an element `H in H` has the form

\[
H=(H_l)_{l\in L},
\qquad
H_l\in\mathbb R^{n_l}.
\]

For example, a single HVD state could contain components such as

```text
spectral_state       : R^4096
control_state        : R^6
identity_embedding   : R^1024
homeostatic_state    : R^11
resource_state       : R^32
```

without asserting that these components inhabit the same semantic coordinate system.

### 5.0.1 Why use a direct sum?

Because `L` is finite in the current formulation, the direct sum is algebraically isomorphic to the Cartesian product

\[
\prod_{l\in L}\mathbb R^{n_l}
\]

and, after choosing an ordering of labels, can also be flattened into an ordinary vector space

\[
\mathbb R^N,
\qquad
N=\sum_{l\in L} n_l.
\]

Therefore the architectural significance of the direct-sum notation is not that finite direct sums possess some exotic algebraic property unavailable to ordinary vectors.

The significance is **semantic typing**.

A flattening map

\[
F:
\bigoplus_{l\in L}\mathbb R^{n_l}
\rightarrow
\mathbb R^N
\]

can always be constructed once an ordering convention is chosen. But the flattened vector alone no longer tells the system which coordinates belong to which semantic component unless the label schema is preserved separately.

HTLA therefore treats

```text
(label, dimension, coordinate contract)
```

as part of the mathematical interpretation of state.

This prevents an implementation from silently assuming, for example, that coordinate `17` of a 4,096-dimensional spectral representation has any meaningful relationship to coordinate `17` of an unrelated control vector.

The governing distinction is

```text
shared record != shared coordinate semantics
```

and

```text
flattenable != semantically interchangeable
```

### 5.0.2 The label schema is part of the contract

For an HTLA component, dimensionality alone is not a sufficient type.

In a concrete implementation, a label should be understood as identifying a component contract containing at least conceptually:

```text
label identity
dimension
scalar/domain type
coordinate semantics
encoding convention
units or normalization convention, where applicable
schema/version information
compatible transforms
```

Thus two components that both happen to inhabit `R^1024` are not automatically interchangeable.

For example,

```text
identity_hypervector : R^1024
```

and

```text
language_hypervector : R^1024
```

have equal dimensionality, but equality of dimension does not establish semantic compatibility.

An explicit mapping is still required if one is to influence or be compared with the other.

### 5.0.3 Algebraic zero is not epistemic absence

HTLA must also preserve the distinction between a mathematical zero and a missing observation.

The vector

\[
H_l=0
\]

is a valid element of `R^(n_l)`.

It therefore cannot automatically mean:

```text
missing
unobserved
unavailable
unknown
sensor failure
not applicable
```

Those are epistemic or schema-level states and should be represented through separate validity information, masks, typed states, metadata, or another explicit mechanism.

Consequently,

```text
zero value != unavailable value
```

This distinction becomes important when HTLA state is consumed by Cyrae, HIGC, THDE, or any other subsystem whose decisions depend on whether a quantity was actually observed.

## 5.1 Transdimensional Linear Operators

Let `S` be a source-label set and `T` a target-label set.

Define

\[
\mathcal X_S
=
\bigoplus_{s\in S}\mathbb R^{p_s}
\]

and

\[
\mathcal X_T
=
\bigoplus_{t\in T}\mathbb R^{q_t}.
\]

An HTLA linear transformation

\[
\mathcal L:
\mathcal X_S
\rightarrow
\mathcal X_T
\]

is represented by a family of typed blocks

\[
\mathcal L
=
[L_{t,s}]_{t\in T,\;s\in S},
\]

with

\[
L_{t,s}
\in
\mathbb R^{q_t\times p_s}.
\]

For an input

\[
x=(x_s)_{s\in S},
\]

the output component corresponding to target label `t` is

\[
y_t
=
\sum_{s\in S}
L_{t,s}x_s.
\]

Every term in this sum lies in `R^(q_t)`, so the summation is dimensionally well-defined.

The complete output is

\[
y=(y_t)_{t\in T}.
\]

### 5.1.1 What "transdimensional" means here

The term **transdimensional** does not imply a mysterious operation outside ordinary linear algebra.

It means that HTLA permits explicitly typed mappings between components of different dimensions:

\[
L_{t,s}:
\mathbb R^{p_s}
\rightarrow
\mathbb R^{q_t}
\]

where it is entirely possible that

\[
p_s\neq q_t.
\]

A block may therefore be:

```text
square
tall
wide
injective
surjective
rank-deficient
approximately invertible
non-invertible
```

depending on its dimensions and rank.

Dimension change alone provides no guarantee of invertibility or information preservation.

### 5.1.2 Sparse semantic coupling

If source component `s` has no configured linear influence on target component `t`, HTLA can represent that relationship with

\[
L_{t,s}=0.
\]

This has a specific interpretation:

> the current operator defines no linear coupling from source label `s` to target label `t`.

It should not be interpreted as:

> the relationship exists but is unknown.

Those cases are different.

Thus:

```text
zero operator block = configured absence of coupling
```

whereas an unresolved or unknown mapping should be represented explicitly rather than silently converted into a zero block.

This makes block sparsity more than an implementation optimization. It allows the operator itself to encode which semantic relationships have actually been defined.

For example:

```text
                    TARGETS
                A       B       C
              +-------+-------+-------+
SOURCE X      | L_AX  |   0   | L_CX  |
              +-------+-------+-------+
SOURCE Y      |   0   | L_BY  |   0   |
              +-------+-------+-------+
SOURCE Z      | L_AZ  | L_BZ  |   0   |
              +-------+-------+-------+
```

defines an explicit semantic coupling topology.

### 5.1.3 Identity operator

For a fixed label schema `L`, the HTLA identity operator is block diagonal:

\[
\mathcal I
=
[I_{l,m}],
\]

where

\[
I_{l,l}=I_{n_l}
\]

and

\[
I_{l,m}=0
\qquad
l\neq m.
\]

It follows that

\[
\mathcal I H=H.
\]

This is useful because identity is defined component-by-component without requiring an arbitrary flattened coordinate convention.

### 5.1.4 Operator composition

Suppose

\[
\mathcal M:
\bigoplus_{s\in S}\mathbb R^{p_s}
\rightarrow
\bigoplus_{u\in U}\mathbb R^{r_u}
\]

and

\[
\mathcal L:
\bigoplus_{u\in U}\mathbb R^{r_u}
\rightarrow
\bigoplus_{t\in T}\mathbb R^{q_t}.
\]

Then the composition

\[
\mathcal L\circ\mathcal M
\]

is well-typed and has block representation

\[
(\mathcal L\circ\mathcal M)_{t,s}
=
\sum_{u\in U}
L_{t,u}M_{u,s}.
\]

Each product has dimensions

\[
(q_t\times r_u)(r_u\times p_s)
=
q_t\times p_s.
\]

The intermediate label set `U` therefore plays the role of an explicitly typed contraction index.

This is ordinary block-matrix algebra, but the labels prevent dimensionally valid yet semantically unintended compositions from being treated as automatically meaningful.

For that reason, HTLA is better described as **label-typed block linear algebra** than as a mathematical grading in the strict abstract-algebraic sense unless an additional formal grading law is explicitly defined.

## 5.2 Label-Aware Metrics, Kernels, and Similarity

Similarity between heterogeneous HVD states must also respect their label structure.

There are two importantly different cases.

### 5.2.1 Aligned-label weighted inner product

Suppose `H` and `K` have the same label schema and corresponding components live in compatible spaces.

A simple weighted bilinear form is

\[
\langle H,K\rangle_w
=
\sum_{l\in L}
w_l
\langle H_l,K_l\rangle,
\]

where

\[
w_l\ge 0.
\]

If every included weight satisfies

\[
w_l>0,
\]

then this defines an inner product over the included HTLA space.

The induced norm is

\[
\|H\|_w
=
\sqrt{
\sum_{l\in L}
w_l\|H_l\|_2^2
}.
\]

If some `w_l=0`, the resulting quantity is only a **seminorm** over the full space because nonzero state may exist entirely inside zero-weighted components.

This distinction matters if the metric is being used in a proof or optimization procedure.

A normalized aligned-label cosine may then be defined as

\[
\operatorname{sim}_w(H,K)
=
\frac{
\langle H,K\rangle_w
}{
\|H\|_w\|K\|_w+\epsilon
},
\]

where `epsilon > 0` protects the numerical implementation against division by zero.

The value of `epsilon` is a numerical safeguard, not part of the mathematical definition of cosine similarity itself.

### 5.2.2 Cross-label compatibility

The more interesting case occurs when a component under one label is allowed to interact with a different label.

Let

\[
P_{l\rightarrow m}:
\mathbb R^{n_l}
\rightarrow
\mathbb R^{n_m}
\]

be an explicitly defined compatible map.

A general cross-label compatibility score may then be written

\[
C_W(H,K)
=
\sum_{l,m}
w_{lm}
\left\langle
P_{l\rightarrow m}H_l,
K_m
\right\rangle.
\]

This formulation is architecturally useful because a comparison between different semantic components cannot occur accidentally.

It requires an explicit declaration of:

```text
source label
target label
compatible map
weight
```

For example:

```text
spectral_state
    |
    | P_spectral->concept
    v
concept_state
```

makes the cross-modal relation visible in the model.

### 5.2.3 A general cross-label score is not automatically an inner product

This point is mathematically important.

The expression

\[
C_W(H,K)
\]

is **not automatically an inner product**.

For an actual inner product, the induced global bilinear operator must satisfy appropriate properties including symmetry and positive definiteness.

In flattened notation, suppose the cross-label construction corresponds to an operator `A_W` such that

\[
K_W(H,K)
=
H^T A_W K.
\]

For this to define an inner product, one requires at minimum

\[
A_W=A_W^T
\]

and

\[
A_W\succ 0.
\]

If merely

\[
A_W\succeq 0,
\]

the construction may define a positive-semidefinite kernel or seminorm rather than a strict norm over the entire space.

Without these conditions, `C_W` should be called a:

```text
compatibility score
bilinear score
directed cross-label similarity
```

rather than an inner product.

This avoids incorrectly applying inner-product geometry to an arbitrary directed semantic relationship.

### 5.2.4 Normalization of general compatibility scores

If the cross-label operator has been proven symmetric positive semidefinite, one may define

\[
\|H\|_W
=
\sqrt{K_W(H,H)}
\]

and then

\[
\operatorname{sim}_W(H,K)
=
\frac{
K_W(H,K)
}{
\|H\|_W\|K\|_W+\epsilon
}.
\]

If those kernel conditions have **not** been established, a safer normalized compatibility measure uses independently valid norms in the denominator, for example

\[
\operatorname{score}_W(H,K)
=
\frac{
C_W(H,K)
}{
\|H\|_{\alpha}
\|K\|_{\beta}
+\epsilon
},
\]

where

\[
\|H\|_{\alpha}^2
=
\sum_l\alpha_l\|H_l\|_2^2
\]

and

\[
\|K\|_{\beta}^2
=
\sum_m\beta_m\|K_m\|_2^2,
\]

with strictly positive normalization weights on the participating components.

This preserves numerical comparability without claiming a geometric property that has not been proven.

### 5.2.5 Similarity is derived evidence, not identity authority

Regardless of which valid similarity construction is used, the result remains a similarity measurement.

Nexus deliberately rejects the inference

\[
\operatorname{sim}(H,K)\approx 1
\]

therefore

\[
H\text{ and }K\text{ have the same identity}.
\]

It likewise rejects

\[
\operatorname{sim}(H,K)\approx 1
\]

therefore

\[
\text{the proposition represented by }K\text{ is true}.
\]

The correct relation is closer to:

```text
high similarity
      |
      v
strong retrieval / comparison evidence
      |
      X
      +--> does not independently establish identity
      +--> does not independently establish truth
      +--> does not independently establish authorization
```

ANN/HNSW indexes may accelerate the discovery of states with high HTLA-derived similarity, but those indexes remain derived structures.

Thus:

```text
similarity != identity
similarity != truth
similarity != continuity
similarity != authorization
```

## 5.3 Dimension-Changing Morphisms and Explicit Distortion

HTLA permits mappings between component spaces of different dimensions, but it does not declare such transformations lossless by default.

Consider

\[
E_{s\rightarrow t}:
\mathbb R^{p_s}
\rightarrow
\mathbb R^{q_t}
\]

defined by

\[
E_{s\rightarrow t}(x)=Px,
\]

where

\[
P\in\mathbb R^{q_t\times p_s}.
\]

The properties of this transformation depend on the rank and geometry of `P`.

If

\[
q_t<p_s,
\]

then an arbitrary linear map cannot be injective over the entire source space unless the effective source is restricted to a lower-dimensional subset.

Information in the null space

\[
\ker(P)
\]

cannot be recovered from `Px`.

Therefore:

```text
dimension reduction != lossless transformation
```

### 5.3.1 Random projection

One historically useful HTLA morphism is a suitably normalized random projection.

For a finite set of `N` points, Johnson-Lindenstrauss-type results show that there exist projections into a dimension approximately scaling as

\[
k
=
O\left(
\frac{\log N}{\varepsilon^2}
\right)
\]

up to theorem-specific constants and refinements, such that pairwise distances are preserved within a multiplicative distortion approximately bounded by

\[
1-\varepsilon
\]

and

\[
1+\varepsilon
\]

with an associated probabilistic guarantee.

The architectural conclusion is deliberately modest.

It is **not**:

```text
random projection makes dimension change lossless
```

It is:

```text
for a specified finite domain,
under stated assumptions,
a randomized embedding can preserve selected geometric
relationships within a quantified distortion bound
```

The guarantee concerns the geometry specified by the theorem. It does not imply preservation of every semantic property carried by the original representation.

### 5.3.2 Every dimension-changing transform needs a contract

A production HTLA morphism should therefore carry an explicit transformation contract describing, where applicable:

```text
source label
target label
source dimension
target dimension
construction method
rank
reference domain
expected distortion
measured distortion
failure probability, if probabilistic
reconstruction method
reconstruction error
version / provenance
```

A transformation should not become semantically trusted merely because its output dimension matches another component.

### 5.3.3 Regularized reconstruction

Let

\[
P
=
U\Sigma V^T
\]

be a singular-value decomposition of the projection matrix.

A Tikhonov-regularized inverse can be written in singular-value form as

\[
P^+_{\lambda}
=
V
\operatorname{diag}
\left(
\frac{\sigma_j}
{\sigma_j^2+\lambda}
\right)
U^T,
\qquad
\lambda>0.
\]

Equivalently, using compatible rectangular-matrix notation,

\[
P^+_{\lambda}
=
V
(\Sigma^T\Sigma+\lambda I)^{-1}
\Sigma^T
U^T.
\]

Given an encoded state

\[
y=Px,
\]

one may construct

\[
\hat x
=
P^+_{\lambda}y.
\]

Reconstruction error is then explicitly measurable:

\[
e_{rec}(x)
=
\|x-\hat x\|_2.
\]

The system can therefore reason about reconstruction quality instead of pretending that a dimension-changing operation possessed an exact inverse.

### 5.3.4 Irrecoverable information and regularization bias

Even a mathematically correct pseudoinverse cannot recover information that was eliminated by the forward map.

If

\[
v\in\ker(P),
\]

then

\[
P(x+v)=Px.
\]

The encoded state cannot distinguish `x` from `x+v`.

Therefore no decoder observing only `Px` can uniquely reconstruct the discarded null-space component.

Regularization additionally introduces controlled bias by suppressing inversion along poorly conditioned singular directions.

This produces a useful architectural rule:

```text
inverse estimate != original state
```

unless exact invertibility has separately been established.

The reconstructed object should therefore carry transformation provenance and, where relevant, an uncertainty or error descriptor.

### 5.3.5 Composition accumulates transformation obligations

If state passes through multiple morphisms,

\[
x
\xrightarrow{P_1}
z
\xrightarrow{P_2}
y,
\]

then the combined map is

\[
y=P_2P_1x.
\]

Even if both transforms individually have bounded errors over their intended domains, the composite transformation requires its own error reasoning.

Nexus therefore should not treat a sequence of individually acceptable approximate projections as automatically equivalent to an exact end-to-end transformation.

The relevant invariant is:

```text
approximation provenance composes;
exactness does not appear by composition
```

## 5.4 Low-Rank Block Compression

HTLA's block structure also provides a natural unit for controlled operator compression.

Consider a block

\[
L_{t,s}
\in
\mathbb R^{q_t\times p_s}
\]

with singular-value decomposition

\[
L_{t,s}
=
U\Sigma V^T.
\]

For a selected rank `r`, define the truncated approximation

\[
\widetilde L_{t,s}
=
U_r\Sigma_rV_r^T.
\]

By the Eckart-Young-Mirsky theorem, truncated SVD gives an optimal rank-`r` approximation under the Frobenius norm and spectral norm.

The blockwise Frobenius error is

\[
\|L_{t,s}-\widetilde L_{t,s}\|_F^2
=
\sum_{j>r}
\sigma_j^2.
\]

Thus compression error is directly measurable from the discarded singular spectrum.

### 5.4.1 Different semantic blocks may use different ranks

There is no requirement that every HTLA block use the same compression rank.

One may select

\[
r_{t,s}
\]

independently for each semantic relationship.

For example:

```text
identity -> control      rank 32
spectral -> concept      rank 128
resource -> control      rank 8
language -> actuator     absent / zero block
```

This allows the compression policy to respect the information complexity of each relationship instead of forcing one global approximation budget.

### 5.4.2 Global block error

Let `L` be the complete block operator and `L_tilde` its blockwise compressed approximation.

Because the blocks occupy disjoint matrix regions, the global Frobenius error satisfies

\[
\boxed{
\|\mathcal L-\widetilde{\mathcal L}\|_F^2
=
\sum_{t,s}
\|L_{t,s}-\widetilde L_{t,s}\|_F^2
}
\]

and therefore

\[
\|\mathcal L-\widetilde{\mathcal L}\|_F^2
=
\sum_{t,s}
\sum_{j>r_{t,s}}
\sigma_{t,s,j}^2.
\]

This provides an exact accounting identity for Frobenius error across independently compressed blocks.

### 5.4.3 Error propagated into state

Compression error at the operator level also bounds output error.

Let

\[
E
=
\mathcal L-\widetilde{\mathcal L}.
\]

For input state `x`,

\[
\mathcal Lx-\widetilde{\mathcal L}x
=
Ex.
\]

Therefore,

\[
\|\mathcal Lx-\widetilde{\mathcal L}x\|_2
\le
\|E\|_2\|x\|_2
\]

and, because

\[
\|E\|_2\le\|E\|_F,
\]

one obtains the looser but readily computable bound

\[
\|\mathcal Lx-\widetilde{\mathcal L}x\|_2
\le
\|E\|_F\|x\|_2.
\]

Thus a compression budget can be translated into an explicit upper bound on induced state error.

Where tighter guarantees are needed, the system can maintain per-block operator norms or empirically calibrated domain-specific error bounds.

### 5.4.4 Storage and computational benefit

An uncompressed block requires approximately

\[
q_tp_s
\]

scalar parameters.

A rank-`r` factorization requires approximately

\[
r(q_t+p_s+1)
\]

parameters when `U_r`, `V_r`, and the singular values are represented separately.

Low-rank compression is therefore advantageous when

\[
r(q_t+p_s+1)
\ll
q_tp_s.
\]

Application can similarly be factored:

\[
L_{t,s}x_s
\approx
U_r
\left[
\Sigma_r
\left(
V_r^Tx_s
\right)
\right],
\]

which avoids materializing the full dense block.

This matters operationally for HVD because large semantic mapping families can be compressed independently while retaining their labels, provenance, and error contracts.

The important point is not simply:

```text
SVD saves memory
```

but:

```text
HTLA permits approximation to remain attached to the exact
semantic relationship being approximated.
```

## 5.5 HTLA as a Mathematical ABI

The phrase **mathematical ABI** should be understood carefully.

HTLA is not, by itself, a binary serialization format or physical storage layout.

Rather, it defines a stable semantic contract between components of the Nexus architecture.

A consumer of an HTLA state should be able to determine:

```text
which semantic components exist
what space each component inhabits
which transformations are permitted
which cross-label relationships are explicit
which approximations have been introduced
what metric or kernel is being applied
what error contracts accompany dimension changes
```

Physical representations may differ.

The same logical component could be stored as:

```text
dense floating-point memory
quinary HSL encoding
packed bit planes
memory-mapped storage
device-resident state
compressed factors
COW-shared TMS state
```

provided that the representation preserves or explicitly transforms the declared HTLA semantics.

Thus:

```text
HTLA semantics != physical encoding
```

and:

```text
HTLA label != storage address
```

TMS may alter physical realization while the HTLA component contract remains stable.

## 5.6 Core HTLA Invariants

The architecture can therefore summarize the linear layer with a small set of invariants.

### 1. Heterogeneous dimensions remain explicitly typed

\[
H_l\in\mathbb R^{n_l}
\]

does not imply semantic compatibility with another component merely because its dimension happens to equal `n_l`.

```text
equal dimension != equal meaning
```

### 2. Flattening does not erase semantic obligations

A direct-sum state can be flattened computationally, but any operation relying on that flattening must preserve the label/schema mapping.

```text
flattened representation != untyped state
```

### 3. Cross-label interaction must be explicit

A component under one label does not automatically interact with another.

Such interaction requires a declared block or compatible transform.

```text
possible multiplication != authorized semantic mapping
```

### 4. Zero and missing are different

```text
0 != UNAVAILABLE
```

A valid zero-valued component must not be confused with absence of evidence or failed observability.

### 5. Dimension change carries an error contract

```text
dimension change != guaranteed information preservation
```

Any approximate morphism must expose the assumptions and distortion under which it is accepted.

### 6. Reconstruction does not imply reversibility

```text
decoder output != proof of exact inverse
```

A pseudoinverse or learned decoder may provide an approximation without recovering information destroyed by the forward transformation.

### 7. Similarity is not authority

```text
high similarity != same identity
high similarity != truth
high similarity != continuity
high similarity != authorization
```

### 8. Compression must remain measurable

Approximation is permitted, but its error must remain quantifiable at the block or operator level.

```text
compressed != semantically unaccountable
```

### 9. Physical realization is independent of HTLA meaning

TMS may move, share, replicate, compress, or otherwise reorganize an HTLA component without automatically changing what that component means.

```text
change in realization !=> change in semantic identity
```

---

HTLA therefore gives Nexus a mathematically ordinary but architecturally disciplined foundation: finite-dimensional linear algebra organized by explicit semantic labels, typed transformations, declared cross-component relationships, and measurable approximation.

Its novelty is not that block matrices, direct sums, kernels, pseudoinverses, random projections, or SVD are individually new mathematical objects.

The architectural contribution is their use as a **semantic contract for heterogeneous cognitive state**.

That contract prevents convenience operations such as flattening, similarity search, dimensional projection, or compression from silently erasing distinctions that higher layers of Nexus depend upon.
